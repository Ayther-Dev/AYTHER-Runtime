# AYTHER Runtime v0.1.0-beta.5

This beta moves the Engine lock from `v0.1.0-rc.8` to `v0.1.0-rc.9`, which
teaches the runtime to read a Sequence's SEGMENTATION STEP from the pack.

- Until now an `[[event]]` of `audio_events.toml` could only state its WINDOW:
  how long the replacement claims, mutes and sounds. The runtime therefore
  segmented by that window, which is a different question — how soon a new
  occurrence of the trigger means a NEW pass. Two consequences: a Sequence
  whose HD is longer than its musical phrase never re-anchored on its own
  period, and a phrase whose last note rings past the loop point swallowed the
  pass that starts there (Golden Axe, "OST - Wilderness": one sustained note
  ringing four frames past the loop point moved the second pass 106 frames
  away, onto a frame where the phrase does not begin).
- The new `span` key is OPTIONAL and its absence keeps the previous behaviour,
  so every pack built before it plays exactly as it did. The correction reaches
  a pack when its author re-exports it.
- The lock carries the four rc.9 archives with their published SHA-256 values,
  the checksum-file hash and the SLSA source ref; CMake, the CI bootstrap gate,
  the contract tests and the documentation follow the lock.
- The Engine package version stays `0.1.0`, so the supported range
  `>=0.1.0,<0.2.0` and the Runtime-Play protocol v1 are unchanged. The Engine's
  C ABI revision also stays at 7: the new field reuses padding the struct
  already had, so no offset moves. The rc.6 reload-path workaround is kept.
- No Runtime feature or wire-protocol change. `--trust-registry`, the fatal
  pack diagnostics and the exit codes are those of beta.4.

See [Runtime-Engine compatibility](../runtime-engine-compatibility.md) and
the [changelog](../../CHANGELOG.md).
