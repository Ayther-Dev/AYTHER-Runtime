# AYTHER Runtime v0.1.0-beta.6

Play CE can now request a reservation of the ROM and the pack with --rom-revision and --pack-revision. Runtime checks the tokens and confirms AYTHER_RESERVATION 1 before continuing. This lets the launcher hand its reservations over to the session process without accepting a different revision of the file.

On Windows, the reservation lasts for the whole session and prevents writing, deleting and renaming. A different revision or an inaccessible file prevents the handover from being confirmed. Platforms without support reject explicit requests; a launch without these options keeps the previous validations.

Engine stays at v0.1.0-rc.9, package 0.1.0 and core C ABI 7. Windows consumes engine-vpx with SHA-256 2d70dc74f4de5db4a21e71185eab12ca2aebea533f53fb21d5d9a710e13d1f2d. The Runtime–Play status protocol remains at v1; the reservation confirmation line is additional and optional.

The release includes native tests for reservation and release, revision rejection, and regression of the launch without reservations. The publishing process runs the suite of each platform. The handover with tokens generated by Play CE is also validated against the distributed Windows executable.

Scope: launch compatibility. It contains no audio fixes, Engine changes, take replay or QA instrumentation. Contract: [reservations](../specs/runtime-reservations.md).
